Lesson 91 of the DevOps Engineering Bootcamp, the seventh lesson of Maven. Your jar works on your laptop, but your teammates cannot use it until you publish it with mvn deploy. This lesson is a live demo on a real Sonatype Nexus Repository, from the very first login to a working package feed. You learn install vs deploy, snapshot vs release, and the distributionManagement block. Then the rule that surprises everybody: a release can never be replaced.

The demo goes from simple to advanced: the first-run setup wizard, a tour of the Nexus screens (sidebar, repository list, hosted vs proxy vs group), creating corp-snapshots and corp-releases with the right policies, deploying a snapshot twice (two timestamped builds), publishing a release, the HTTP 409 refusal when you deploy it again, browsing the result and its SHA-1 checksum, then the advanced part: the maven-public group and a Maven Central proxy cache filled by your own build. The fix for a bad release is never an overwrite: publish 1.0.1.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab91.sh and shortcuts91.sh). Install with: sudo install -m 755 lab91.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short name with: source shortcuts91.sh (without it, use sudo --preserve-env=NEXUS_PASS lab91.sh up, check, down). You need an Ubuntu virtual machine with root, a JDK, Maven, python3 and curl (for example: sudo apt install -y openjdk-21-jdk-headless maven python3 curl), internet access, about 3 GB of free memory and 1.5 GB of disk. The first lab up downloads Sonatype Nexus Repository Community Edition 3.98.1 (about 525 MB) from download.sonatype.com, writes a project into /opt/lab91 and starts Nexus on port 8081 as a dedicated user. lab down stops Nexus and removes everything. Only run it in your own virtual machine.

Honest notes: the browser and terminal segments are one real, continuous recording on Ubuntu 24.04 with Maven and OpenJDK 21, against a real Nexus Repository Community Edition 3.98.1 and the real Maven Central. The Nexus license agreement is yours to read and accept in your own lab; I accepted it for the demo instance only. The setup wizard also asks you to acknowledge a required daily usage report; if Nexus cannot send it for 30 days it becomes read only, which matters for a long-lived server but not for this lab. The admin password on screen is a throwaway value that only exists in my recording environment; never show or reuse a real one. I used Nexus's classic screens. Your Nexus may show the new look first, and menus or colors can differ in other versions. The ideas, task, rubric and quiz screens are labelled illustrations, not captures. The lab was run end to end before this lesson: it fails 0 of 5 at the start, passes 5 of 5 after a reference solution, and lab down leaves nothing behind; only one style of solution was tested, so a different valid approach could be judged wrongly by the checker. The narration is synthetic speech. Your own run is unverified until you do it.
