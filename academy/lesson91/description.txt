Lesson 91 of the DevOps Engineering Bootcamp, the seventh lesson of Maven. Your jar works on your laptop, but your teammates cannot use it until you publish it with mvn deploy. You learn the difference between install (your own .m2 folder) and deploy (a shared repository), the two kinds of version, snapshot and release, and the distributionManagement block that tells Maven where to upload. Then the rule that surprises everybody: a release can never be replaced. In the live demo you deploy a snapshot twice and get two timestamped jars, change the version to 1.0.0 and publish a release, then deploy it again and see HTTP 409 Conflict. The fix is never an overwrite: publish 1.0.1. Then you do it yourself: five checks, all must pass.

Objectives covered: MC10-O07 (publish snapshot and release artifacts to a repository manager)

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab91.sh and shortcuts91.sh). Install with: sudo install -m 755 lab91.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short name with: source shortcuts91.sh (without it, use sudo lab91.sh up, check, down). You need an Ubuntu virtual machine with root, a JDK, Maven and python3 (for example: sudo apt install -y openjdk-21-jdk-headless maven python3) and internet access to Maven Central for the build plugins. The lab starts a small local stand-in repository server with a login on port 8092, writes a project into /opt/lab91, and lab down stops the server and removes the folder. Only run it in your own virtual machine.

Honest notes: the terminal segments are real recordings on Ubuntu 24.04 with Maven 3.9.11 and OpenJDK 21. The repository in the demo is a small local stand-in server I wrote that accepts uploads with a login and refuses to overwrite a release; it is not a real repository manager such as Nexus or Artifactory. Real managers behave the same way for this rule, but their screens, settings and error texts differ, and I did not test one. The password on screen is a throwaway demo value that only exists in my recording environment. My recording computer cannot reach Maven Central, so the plugins came from a local copy built from Ubuntu's packaged Maven files through an extra mirror that is not shown. The ideas, task, rubric and quiz screens are labelled illustrations, not captures. The lab was run end to end before this lesson: it fails 0 of 5 at the start, passes 5 of 5 after a reference solution, and lab down leaves nothing behind. On your machine the plugins download from Maven Central, which I could not test, and only one style of solution was tested, so a different valid approach could be judged wrongly by the checker. The narration is synthetic speech. Your own run is unverified until you do it.
