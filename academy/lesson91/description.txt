Lesson 91 of the DevOps Engineering Bootcamp, the seventh lesson of Maven. Your jar works on your laptop, but your teammates cannot use it until you publish it with mvn deploy. This is CloudCart v0: one module, cart-core, becomes a shared package. You learn install versus deploy, snapshot versus release, and the distributionManagement block. Then a full live demo in a web page and a terminal, in one continuous recording: you log in to a repository manager, create a snapshot repository and a release repository, deploy a snapshot twice and see two timestamped jars arrive, publish release 1.0.0, then deploy it again and watch HTTP 409 Conflict appear on the Events page. The fix is never an overwrite: publish 1.0.1. Then you do the lab yourself: five checks, all must pass.

Objectives covered: MC10-O07 (publish snapshot and release artifacts to a repository manager)

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab91.sh and shortcuts91.sh). Install with: sudo install -m 755 lab91.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short name with: source shortcuts91.sh (without it, use sudo lab91.sh up, check, down). You need an Ubuntu virtual machine with root, a JDK, Maven and python3 (for example: sudo apt install -y openjdk-21-jdk-headless maven python3) and internet access to Maven Central for the build plugins. The lab starts a small local stand-in repository manager with a web page and a login on port 8092 (open http://localhost:8092/ui, user dev, password in /opt/lab91/pass.txt), writes a project into /opt/lab91, and lab down stops the server and removes the folder. Read TASKS.txt in that folder: you create the two repositories in the web page yourself. Only run it in your own virtual machine.

Honest notes: the browser and terminal segments are one real continuous recording on Ubuntu 24.04 with Maven 3.9.11 and OpenJDK 21. The repository manager in the demo is a small local stand-in web app I wrote that accepts uploads with a login and refuses to overwrite a release; it is not Nexus or Artifactory. Real managers follow the same rule, but their screens and error texts differ, and I did not test one. The real Nexus gets its own masterclass later, where CloudCart v1 uses it. The password on screen is a throwaway demo value that only exists in my recording environment. My recording computer cannot reach Maven Central, so the plugins came from a local copy built from Ubuntu's packaged Maven files through an extra mirror that is not shown. The ideas, task, rubric and quiz screens are labelled illustrations, not captures. The lab was run end to end before this lesson: it fails 0 of 5 at the start, passes 5 of 5 after a reference solution, and lab down leaves nothing behind. On your machine the plugins download from Maven Central, which I could not test, and only one style of solution was tested, so a different valid approach could be judged wrongly by the checker. The narration is synthetic speech. Your own run is unverified until you do it.
