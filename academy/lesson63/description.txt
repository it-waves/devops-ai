Lesson 63 of the DevOps Engineering Bootcamp, the seventh lesson of the Git and GitHub masterclass, from beginner to mastery. You learn how to undo mistakes in Git and how to choose the right tool: git restore for edits that are not committed (and for unstaging), git revert for a commit that is already shared, git reset for commits that exist only on your computer, and the reflog as the safety net when something goes wrong. Live on Ubuntu you see: git status -s, git restore, git restore --staged, git restore --source=HEAD~2, git revert --no-edit HEAD, git reset --soft, git reset (mixed) and git reset --hard, why you never reset shared history, and how git reflog and git reset --hard HEAD@{1} bring back a commit lost by a bad hard reset. The lab has a checker that says PASS or FAIL for four checks, a pass/fail rubric, and cleanup.
