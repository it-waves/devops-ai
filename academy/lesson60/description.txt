Lesson 60 of the DevOps Engineering Bootcamp, the fourth lesson of the Git and GitHub masterclass, from beginner to mastery. You learn rebasing: the other way to combine diverged work. You see how merge and rebase differ (a merge commit versus replaying your commits on top of the latest code), why rebasing and amending rewrite history with new hashes, and the golden rule: never rebase commits other people already have. Then, live on Ubuntu: fixing the last commit with git commit --amend, rebasing a feature branch onto main with git rebase, a fast-forward merge for a perfectly straight history, and a rebase conflict step by step (git status during a rebase, why the two sides are swapped, git add, git rebase --continue, and git rebase --abort as the escape hatch). The lab has a checker that says PASS or FAIL for four checks, a pass/fail rubric, and cleanup.
