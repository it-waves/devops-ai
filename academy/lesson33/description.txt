Lesson 33 of the DevOps Engineering Bootcamp, the eighth lesson of the Linux administration masterclass. A server needs room to work, and a full disk stops things. You learn the path from disk to filesystem to mount point. You check free space with df, find what is using it with du, make a practice disk from an ordinary file, format it with mkfs.ext4 and read its UUID with blkid, mount it and prove it with df and lsblk, fill it on purpose and read the no space left error, free the space, and grow it: bigger disk, filesystem check, resize2fs, mount again. You see what goes in /etc/fstab to mount at boot, and why you use the UUID. You finish with common myths, a six-point pass or fail rubric and six tasks to do in your own virtual machine, using a practice file and never a real disk.

Honest notes: every terminal segment is a real recording of real commands on Ubuntu 24.04, including the loop mount, the full disk error and the resize. The disk is a 100 MB file, not a physical disk, so the device is a loop device (loop0) where a real server would show a name like sda or nvme0n1. The sizes and the 86 percent used figure on the first screen come from the recording computer, so yours will differ. The /etc/fstab line is an example drawn as a labelled illustration, not a capture, and I did not edit a real fstab. Typing is timed to the narration, and the yellow highlights were added afterwards. Your own run is unverified until you do it.
