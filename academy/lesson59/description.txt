Lesson 59 of the DevOps Engineering Bootcamp, the third lesson of the Git and GitHub masterclass, from beginner to mastery. You learn to work in parallel without overwriting anyone. You see what a branch really is (a movable name pointing at a commit, with HEAD showing where you are) and the three kinds of merge: fast-forward, a true merge commit with two parents, and a conflict. Then, live on Ubuntu: git branch, git switch -c, committing on a branch with git commit -am, git log --oneline --graph --all, and seeing your files swap when you switch back to main. You merge a finished branch with git merge, read the graph, and delete it safely with git branch -d. Finally the part people fear: conflict markers, git status -s showing UU, git merge --abort as the escape hatch, resolving by hand, git add and git commit to finish. The lab has a checker that says PASS or FAIL for four checks, a pass/fail rubric, and cleanup.
