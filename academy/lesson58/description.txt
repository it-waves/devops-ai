Lesson 58 of the DevOps Engineering Bootcamp, the second lesson of the Git and GitHub masterclass, from beginner to mastery. You take control of what goes into a commit, how to read history, and how to keep junk and secrets out. You see the three snapshots Git compares (working tree, staging area, last commit) and which diff command compares which; then, live on Ubuntu, git status -s with its two columns, git diff, git add, git diff --staged and git restore --staged. You learn what makes a good commit message. You read the past with git log, git show, a single file's history and git blame, and you see the file as it was three commits ago. Finally, ignore files: .gitignore patterns, git check-ignore -v, the trap that ignoring a file Git already tracks does nothing, and git rm --cached to untrack it while keeping it on disk. The lab has a checker that says PASS or FAIL for four checks, a pass/fail rubric, and cleanup.
