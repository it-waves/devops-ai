Lesson 85 of the DevOps Engineering Bootcamp, the first lesson of Maven. One file, the pom, tells Maven your project name, your folders, your libraries and your build steps. You learn its four parts: coordinates (group I D, artifact I D, version), properties, dependencies with a scope, and the build plugins. You see the standard folder layout (src/main/java, src/test/java), what a repository really is (folders named from the coordinates), how a missing dependency fails the build, how to declare it, what the dependency tree shows, and where Maven caches a library on your machine. Then you fix a broken project yourself: five checks, all must pass.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab85.sh and shortcuts85.sh) and academy/lesson85 (INSTALL.txt). Install with: sudo install -m 755 lab85.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short name with: source shortcuts85.sh (without it, use sudo lab85.sh up, check, down). You need an Ubuntu virtual machine with root, a JDK and Maven (for example: sudo apt install -y openjdk-21-jdk-headless maven) and internet access to Maven Central. The lab writes a small project into /opt/lab85; lab down removes the folder. Only run it in your own virtual machine.

Honest notes: the terminal segments and the repository browser are real recordings on Ubuntu 24.04 with Maven 3.9.11 and OpenJDK 21. My recording computer cannot reach Maven Central, so the libraries came from a local copy built from Ubuntu's packaged Maven libraries (the same group, artifact and version folders as Central). That is why the dependency tree shows a helper library version named debian under JUnit; on a normal machine you will see the Central version instead (for example hamcrest-core 1.3). The ideas, task, rubric and quiz screens are labelled illustrations, not captures. The lab was run end to end before this lesson with Ubuntu's copy of the libraries: it fails 0 of 5 at the start, passes 5 of 5 after a reference solution, and lab down leaves nothing behind. On your machine it downloads from Maven Central, which I could not test, and only one style of solution was tested, so a different valid approach could be judged wrongly by the checker. Maven downloads and build times vary. The narration is synthetic speech. Your own run is unverified until you do it.
