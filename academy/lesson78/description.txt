Lesson 78 of the DevOps Engineering Bootcamp, the third lesson of Java Fundamentals for DevOps. "It worked on my laptop" usually means Java looked in different places, or the environment told it something different. Four ideas explain it. A package is a folder path: com.cloudcart.Main lives in com/cloudcart/Main.java. The class path is the list of places Java looks for classes, folders and jar files joined by colons. A dependency is code someone else wrote, shipped as a jar, that you add to the class path. Configuration lives outside the code: environment variables and -D properties. On a real Ubuntu machine you compile a small project that fails at compile time because the jar is missing, add the jar with -cp, look at how the output folders match the package, list what is inside a jar, and run the program. Then you break the class path on purpose and meet NoClassDefFoundError and "Could not find or load main class", and finally change the program's behaviour from outside with STORE_NAME and -Dcurrency. Then you do the lab task yourself: six points, all six must pass.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab78.sh and shortcuts78.sh) and academy/lesson78 (INSTALL.txt). Install with: sudo install -m 755 lab78.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short name with: source shortcuts78.sh (without it, use sudo lab78.sh up, check, down). You need an Ubuntu virtual machine with root and a JDK (for example: sudo apt install openjdk-21-jdk-headless). The lab builds a small project and a jar in /opt/lab78 and removes them on lab down. Only run it in your own virtual machine.

Honest notes: every terminal segment is a real recording of real commands on Ubuntu 24.04 with OpenJDK 21, run in a private mount and network setup on the recording computer. The ideas, messages, task, rubric and quiz screens are labelled illustrations, not captures. The exact wording of Java error messages can differ slightly between Java versions. The class path separator is a colon on Linux and a semicolon on Windows. The lab was run end to end before this lesson: it fails 0 of 5 at the start, passes 5 of 5 after a reference solution, and lab down leaves nothing behind. Only one style of solution was tested, so a different valid approach could be judged wrongly by the checker. The project, jar and file names are invented, and lab is a short name I made for sudo lab78.sh. Typing is timed to the narration. The narration is synthetic speech. Your own run is unverified until you do it.
