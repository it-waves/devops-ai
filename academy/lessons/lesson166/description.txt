Lesson 166 of the DevOps Engineering Bootcamp, SonarQube domain. Run a real analysis of a Java Maven project and watch it appear on your own SonarQube server. You learn how a scan works (build and test, scan, upload, show), the three things every scan needs (the server address, a project key and a token), and then you watch it live: check that the project has no Sonar settings, log in, create a token in My Account, keep it in an environment variable, run the Maven scan with the full plugin name, read the output, and open the new project and its issues in the browser. You finish with the common mistakes and a four-check lab script.

Objectives covered: MC18-O03. Run analysis for a Java Maven project.

Lab files: github.com/it-waves/devops-ai, in academy/lab (lab166.sh and shortcuts166.sh). "scan" runs the Maven command and "lab check" runs four checks (token valid, project exists, analysis uploaded, lines of code counted) and saves results166.txt. Set SONAR_TOKEN to your own token and never store it in a file in a repository. Use your own machine only.

Honest notes: the terminal and browser are a real continuous recording of SonarQube Community Build 26.11 analysing the CloudCart project with the Sonar Maven plugin. The token shown on screen belongs to a throwaway lab server and was deleted afterwards; never show a real token. The terminal output is filtered with grep to show only the important lines. Coverage shows an error because no coverage report was produced yet; the next lessons cover that. The coloured boxes and labels on top are overlays added for teaching. The narration is synthetic speech. The hook, plan, how-it-works, needs, mistakes, lab, your-turn and recap screens are labelled illustrations, not captures.
