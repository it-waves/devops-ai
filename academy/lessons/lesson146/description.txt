Lesson 146 of the DevOps Engineering Bootcamp, the second lesson of the DevOps Fundamentals domain. CI, continuous delivery and continuous deployment sound the same and mean three different things. In this lesson you learn what continuous integration really checks (and what it does not do), how continuous delivery keeps every release ready while a human presses the button, how continuous deployment removes the button so the tests decide, the five things that must be true before you remove the gate (strong tests, small changes, feature flags, fast rollback, monitoring), and how to choose between them by the cost of a mistake. In the live demo, one real pipeline script runs in all three modes: CI stops after the tests, delivery stops and waits for approval, deployment releases by itself. Then a bug is added on purpose, and the tests stop it before it reaches production.

This domain has no lab on purpose: it is about ideas and decisions, so the practice is a plain terminal exercise with a self-check.

Honest notes: the terminal demo is a real recording of a real shell running a small pipeline script written for this lesson. It is a teaching stand-in for a real CI/CD system such as Jenkins or GitHub Actions, which come later in the bootcamp. The narration is synthetic speech. The hook, plan, CI, delivery, deployment, side-by-side lanes, safety, choose, task, files, self-check and recap screens are labelled illustrations, not captures.
