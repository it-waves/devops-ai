Lesson 116 of the DevOps Engineering Bootcamp, and lesson 4 of 5 of the CloudCart v0 project. You work an incident the way an on-call engineer does: symptom, evidence, cause, fix, proof. Then one continuous live terminal recording on real Apache Tomcat 10.1.34 with three real faults: a wrong JAVA_HOME in setenv.sh (startup.sh refuses to run), a Python web server squatting on port 8089 (found with curl and ss, confirmed by a BindException in catalina.out, stopped with pkill), and a truncated war file (a ZipException in the log; 100,000 bytes against the good 296,701). You fix each one with vim and cp, ask for the health page and the product list like a customer, write your three causes in answers.txt, and finish with lab check for 5 of 5.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab116.sh and shortcuts116.sh). Install with: sudo install -m 755 lab116.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short name with: source shortcuts116.sh. You need any Linux machine with root, a JDK, curl, ss and python3 (for example: sudo apt install -y openjdk-21-jdk-headless curl iproute2 python3), internet access, about 1 GB of free memory and ports 8089 and 8099 free. No systemd is needed. The first lab up downloads Tomcat 10.1.34 (about 14 MB) and the app (about 0.3 MB). lab down stops Tomcat and the squatter and removes everything. Only run it on your own machine.

Honest notes: the terminal part is one real, continuous recording on real Apache Tomcat 10.1.34 with the real faults the lab plants. The lab was run end to end: it passes 0 of 5 before you start and 5 of 5 after the tasks, and lab down leaves nothing behind. The app is the prebuilt CloudCart 0.2.0 war from lesson 113. The narration is synthetic speech. The hook, picture, steps, task, rubric and recap screens are labelled illustrations, not captures. Your own run is unverified until you do it.
