Lesson 126 of the DevOps Engineering Bootcamp, and lesson 1 of the Databases for DevOps domain. Your app is slow, shows an error, or lost an order, and nine times out of ten the answer is in the database. This lesson gives you the eight words you need (server, database, schema, table, row and column, connection, transaction, migration), then you use a real PostgreSQL 16 server: connect with psql, read the version, list and describe tables, count rows, read a migrations table, join three tables, check who is connected with pg_stat_activity, and run one transaction that rolls back and one that commits. A rolled-back row still uses up an id, and you see it happen. A lab then judges you from 0 of 5 to 5 of 5.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab126.sh and shortcuts126.sh). Install with: sudo install -m 755 lab126.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short names with: source shortcuts126.sh. You need any Linux machine with root, PostgreSQL server and client (for example: sudo apt install -y postgresql postgresql-client) and port 5461 free. The lab runs its own private PostgreSQL cluster in /opt/lab126 and does not touch the system PostgreSQL. lab down stops it and removes everything. Only run it on your own machine.

Honest notes: the terminal part is one real, continuous recording on real PostgreSQL 16, and the lab was run end to end: it passes 0 of 5 before you start and 5 of 5 after you finish, and lab down leaves nothing behind. The shop database is a tiny teaching example, so real databases are much bigger. The server is configured for local sockets with trust authentication in this lab only: never do that on a real server (we fix that in the next lesson). The narration is synthetic speech. The hook, vocabulary, task, rubric and recap screens are labelled illustrations, not captures. Your own run is unverified until you do it.
