Lesson 147 of the DevOps Engineering Bootcamp, the third lesson of the DevOps Fundamentals domain. Servers fixed by hand cannot be rebuilt, repeated or trusted. In this lesson you learn infrastructure as code (describe servers, networks and databases in files kept in Git, so you get history, review and rollback), why the same code makes identical servers ("cattle, not pets"), configuration management and the desired state, the key word idempotent (run it once or ten times, the result is the same), drift (when a server stops matching its code, and how to detect and fix it), automation and toil, and which tool does what: Terraform, Ansible, Docker, Kubernetes, Jenkins and GitHub Actions. In the live demo, a real terminal runs a naive script twice and breaks the file, then a safe idempotent script (changed on the first run, ok on the second), then a hand edit causes drift, which a check detects and the same code repairs.
