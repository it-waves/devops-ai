Lesson 137 of the DevOps Engineering Bootcamp, and lesson 3 of the Software Testing and QA domain. A test run that looks green on your screen means nothing to a build server: it reads one number, the exit code. In this lesson you learn the ways to run pytest (all tests, one file, one test, a keyword with -k), how to read the dots and letters and the E line of a failure, what exit code 0 and 1 mean, how to find the slowest tests, and how to produce a JUnit XML file for machines and a self-contained HTML report for people. You then open the real HTML report in a browser and click through it. A lab judges you from 0 of 6 to 6 of 6.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab137.sh and shortcuts137.sh). Install with: sudo install -m 755 lab137.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short names with: source shortcuts137.sh. You need any Linux machine with root, python3 and pytest (for example: sudo apt install -y python3-pytest python3-pytest-html), plus a web browser to open the report. The lab creates a small shop project in /opt/lab137 and does not touch anything else. lab down removes it. Only run it on your own machine.

Honest notes: the terminal demo is one real, continuous recording of pytest running on a small Python shop written for this lab, and the HTML report is the real report opened in a real Chrome window. The lab was run end to end: it passes 0 of 6 before you start and 6 of 6 after you finish, with a reference solution, and lab down leaves nothing behind. Failure summaries are shortened in places to keep the screen clean. The narration is synthetic speech. The hook, plan, concept, task, lab info, rubric and recap screens are labelled illustrations, not captures. Your own run is unverified until you do it.
