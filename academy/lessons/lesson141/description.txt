Lesson 141 of the DevOps Engineering Bootcamp, in the Software Testing and QA domain. Tests that never run protect nothing. In this lesson you learn why tests belong in CI, the anatomy of a GitHub Actions workflow (on, permissions, jobs, steps, pinned actions), and what makes a run pass or fail: the exit code. You see pytest and a coverage gate (--cov-fail-under) fail on a planted bug, learn the "|| true" trap that silently kills a gate, why the upload step needs "if: always()", and how a required status check makes red mean stop. You write a real ci.yml, then look at two real GitHub Actions runs of a real repository: one red with an annotation on the exact failing line, one green with a saved coverage report. A lab judges you from 0 of 6 to 6 of 6, and runs your gate against a planted bug.

Get the lab: github.com/it-waves/devops-ai, in academy/lab (lab141.sh and shortcuts141.sh). Install with: sudo install -m 755 lab141.sh /usr/local/sbin/ then run lab up, lab check and lab down after loading the short names with: source shortcuts141.sh. You need python3, pytest, pytest-cov and PyYAML (sudo apt install -y python3-pytest python3-pytest-cov python3-yaml). lab up works only in /opt/lab141 and does not touch anything else. lab down removes everything. Only run it on your own machine.

Honest notes: the terminal demo is a real recording of pytest and the lab judge. The GitHub screens are real screenshots of real runs in github.com/it-waves/devops-ai (run 1 failed on a planted bug, run 2 passed after the fix), shown step by step, not a continuous recording. The required-status-check screen is an unsaved settings form, shown only to explain it. The lab was run end to end: 0 of 6 before you start, 6 of 6 with a reference solution, and lab down leaves nothing behind. The narration is synthetic speech. The hook, plan, concept, task, lab info, rubric and recap screens are labelled illustrations, not captures. Your own run is unverified until you do it.
