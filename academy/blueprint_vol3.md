Covers checklist items 12 to 18. State: DESIGNED.

## 12. Assessment framework
- **Per lesson:** a `check.sh` or test suite that a learner runs themselves (PASS/FAIL, read-only), plus 3 to 5 self-check questions.
- **Per level (P1 to P5):** acceptance criteria written as commands that must succeed. P5 is an unfamiliar scenario with requirements only, solution kept in a separate private folder.
- **Rubric (every P4/P5 and stage exam):** Functionality 30, Security 20, Automation 15, Troubleshooting 15, Documentation 10, Architecture decisions 10. Mandatory gates: security and recovery items must pass regardless of total (pass mark 70).
- **Stage exams:** one unfamiliar scenario at the end of each Stage A to I.
- **Final readiness assessment:** the 14 competencies in directive section 42, scored with the same rubric, then defended in writing.
- **Comprehension validation:** no representative learners are available, so every lesson carries "comprehension validation: PENDING" until real learner feedback exists. Never reported as passed without evidence.

## 13. Production standards (audio/visual)
- **Voice:** Kokoro `am_eric`, speed about 0.97, `pronunciation.json`, loudness about -16 LUFS (EBU R128 measured with ffmpeg `loudnorm`), no music over explanations. Commands appear on screen in full; narration says what they do, not each character.
- **Video:** 1920x1080, 30 fps, navy/cyan identity, readable terminal (minimum 28 px equivalent), captions generated from narration timings (SRT), chapters, thumbnail.
- **Animation:** diagram builds step by step in sync with narration (nodes appear when mentioned), data-flow arrows, highlight on the part being discussed. No static slideshow, no looped decoration.
- **Demonstrations:** real output from real runs (CI transcript), with "captured from a real run" on screen. Illustrations carry an "ILLUSTRATION" badge. Photorealistic 3D only if a scene needs it and a real asset can be produced; none is promised.
- **Sound:** subtle UI sounds only; any music must be licensed or generated by us.

## 16. Production workflow
Plan → research → design (spec + storyboard) → implement lab/code → CI verify → capture transcript → script (pronunciation applied) → TTS → render scenes → frame review → kit → deliver → owner uploads → Studio publish → ledger update. Manifest updated at each milestone with evidence, blocker, next action.

## 17. Risk register
| Risk | Impact | Control |
|---|---|---|
| Cloud labs unverifiable without accounts | cloud MCs stay UNVERIFIED | label levels; request lab account when needed |
| Tool versions drift | outdated lessons | pinned manifests, quarterly review |

| Third-party downloads in CI (Tomcat) | supply-chain risk | pinned version + checksum verification |
| No learner testing | unproven clarity | status PENDING; collect comments/analytics after publish |
